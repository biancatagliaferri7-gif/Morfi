# Validación de salida a piloto

La versión integrada recupera `feature/bianca` en `22d1208fba73433a6e83035eeafee99db59af627`. El código de pedidos, la confirmación `/auth/callback`, el mapa y las reseñas son los de esa rama. No publicar nuevamente el código anterior de `main` ni inicializar de nuevo la base existente.

1. En el Supabase existente, ejecutar primero las consultas de lectura de `MORFI_CHECKOUT_VERIFICACION.sql`. Identificar qué migraciones de Bianca ya están instaladas. No ejecutar todas las variantes SQL del repositorio: `MORFI_CHECKOUT_LISTO.sql` y los tres archivos numerados son alternativas, no pasos acumulativos. Si faltan prerrequisitos, resolverlos antes de desplegar.
2. Ejecutar la versión actual de `morfi_reconciliation_migration.sql` después de las migraciones de registro y checkout de Bianca. Es una transacción: comprueba `payment_method text[]`, el trigger de alta y `delivery_fee_status` antes de modificar. Agrega el registro diferido, la lectura privada de configuración y permisos de stock sujetos a RLS. Conserva pedidos, snapshots y RPCs de Bianca. No aplica ni modifica datos existentes de pedidos. Aunque se hubiera aplicado el archivo antiguo con el mismo nombre, esta nueva revisión debe ejecutarse; el código se distingue en Git.
3. En Vercel configurar `VITE_SUPABASE_URL` y `VITE_SUPABASE_PUBLISHABLE_KEY` con el proyecto existente. Activar `VITE_MORFI_ORDER_CHECKOUT_V2=true` solo si la verificación confirma `morfi_create_order_v2`, la cotización y demás RPCs de checkout. No cambiar el flag sin revisar la base. Hacer un nuevo deploy para incorporar variables.
   Mientras V2 esté desactivado, el comprador puede registrar pedidos básicos con retiro o envío de tarifa definida; el checkout guarda su teléfono en `morfi_profiles` antes de llamar a la RPC anterior. Observaciones, referencias y envíos pendientes de cotización requieren V2. El bloqueo visible en el checkout no se elimina activando solo la variable: la migración debe estar instalada y verificada primero.
4. En Authentication → URL Configuration, usar `https://morfi-ten.vercel.app` como Site URL y permitir `/auth/callback`, `/login` y `/login?recovery=1` en ese dominio. Bianca usa `/auth/callback` para confirmar correo; conservarlo junto con las rutas de recuperación. Si existe un template de correo personalizado, revisarlo con `supabase_confirm_signup_template.html` sin reemplazarlo a ciegas.
   En Authentication → Providers → Email, revisar la política real de contraseñas (longitud, tipos de caracteres y protección de claves filtradas). El formulario explica los motivos que devuelve Supabase; usar una contraseña nueva con mayúsculas, minúsculas, números y un símbolo. Una contraseña hecha solo con el DNI no es apropiada.
5. Crear dos cuentas confirmadas: comprador y vendedor. Probar tanto el registro rápido de vendedor como el completo con mapa y banco. El vendedor configura “Cómo vendés hoy”, publica un producto con stock y una foto. Verificar que la foto se guarda como URL en Storage.
6. Desde el comprador, confirmar y reintentar el mismo pedido. Debe existir una sola orden y un único descuento de stock. Probar retiro, envío gratis, tarifa fija y cotización pendiente. En esta última opción, no se puede despachar ni transferir antes de confirmar el costo.
7. Desde el vendedor, aceptar, preparar, marcar listo y entregar; revisar transferencia y rechazo/cancelación. Recargar ambos navegadores y comprobar Realtime o la actualización de respaldo cada 30 segundos con pestaña visible. Confirmar devolución de stock una sola vez.
8. Desde una tercera cuenta, intentar leer `morfi_managed_business_settings` con un comercio ajeno y modificar su stock: debe rechazarse. Verificar que los datos bancarios y teléfonos privados no se consulten directamente con anon. Probar agotado, cerrado y pago no habilitado.
9. Instalar la PWA y probar red lenta, navegación directa a `/business`, texto ampliado y recuperación de sesión. Sin red se conserva el shell e imágenes públicas visitadas; pedidos y sesión requieren red. Confirmar reseñas después de una entrega.
10. Ejecutar `npm test` y `npm run build` sobre el commit que se despliega. Las pruebas locales de PostgreSQL usan un esquema mínimo, no sustituyen la validación autenticada de Supabase/Storage. Registrar las pruebas de uso con cinco personas antes de difundir la aplicación.
